# 研错库柔和视觉系统研究与改造计划

> 状态：实施中；Token v2、柔和列表代理、题库与笔记工作区第一轮已落地。  
> 日期：2026-07-29  
> 范围：Windows PySide6 / Qt Widgets 客户端。  
> 约束：按公共组件 → 核心页面 → 其余页面渐进迁移，不修改数据库、服务、同步协议或领域规则。

## 1. 结论

研错库可以在现有 Qt Widgets 架构上明显变得更自然、柔和，不需要推翻业务页面，也不需要改成 Web 技术栈。

当前界面的“生硬”并不是单纯因为圆角数值偏小，而是以下因素叠加造成的：

1. 页面由大量连续的水平线、垂直线和满宽矩形选中块构成；
2. 外壳、工作区、面板、列表行之间缺少清晰但柔和的表面层级；
3. 不同组件分别使用 0、4、6、8、10px 圆角，缺少统一的曲率逻辑；
4. 题库和笔记仍明显呈现为 Qt 原生分栏控件，分割线比内容层级更抢眼；
5. 图标体系缺失，大量操作依赖纯文字、字符箭头和文本菜单；
6. 多级标题普遍偏黑、偏粗，留白却没有形成稳定节奏；
7. 空内容区域很大，但空状态、阅读画布和内容焦点没有被表面承接；
8. 当前主题主要解决了“统一颜色”，还没有形成完整的组件形态和交互质感。

因此，下一轮不应继续逐个页面增加圆角，而应建立一套“柔和视觉系统”：

> 以弱边界、分层表面、内缩选中态、稳定留白、统一图标和克制动效，替代连续矩形边框与 Qt 原生控件拼接感。

## 2. 参考目标与边界

### 2.1 值得借鉴的视觉原则

参考截图中的轻量办公产品，可以抽取出以下通用原则：

- 应用主体像一张完整、轻盈的工作台，而不是贴满窗口的表格；
- 导航、目录、列表和详情虽然分层，但不依赖深色边框切割；
- 选中状态通常内缩，并带有适度圆角和低饱和底色；
- 大面板使用相近的白色、灰白色和淡蓝灰色形成层级；
- 图标、文字、间距共同表达结构，边框只承担必要的控件边界；
- 重要操作有清晰颜色，其余操作保持安静；
- 列表行、工具栏和卡片之间存在呼吸感，不追求每一像素都填满；
- 圆角存在层级：小控件、中型面板和应用外壳不是同一个数值。

### 2.2 不应照搬的内容

- 不复制第三方品牌色、Logo、专有图标或具体页面；
- 不为了“像飞书”而引入与学习管理无关的导航层级；
- 不用大量阴影、渐变、玻璃模糊掩盖信息架构问题；
- 不牺牲题目密度、公式阅读面积和键盘效率；
- 不重写数据库、服务、同步协议或录题流程；
- 不把所有组件都做成悬浮卡片，避免“卡片套卡片”。

目标应定义为：

> 保留研错库的学习场景与信息密度，采用自然、柔和、安静的现代桌面组件语言。

## 3. 当前界面诊断

### 3.1 题库页

当前优点：

- 页面主任务已经清楚；
- 顶部操作、搜索、知识树和题目列表已形成基本层级；
- 颜色基本统一，主要动作也已收敛。

主要问题：

| 现象 | 造成的感受 | 根因 |
| --- | --- | --- |
| 工作区四周和内部均使用 1px 直线 | 像表格或后台管理系统 | `LibraryWorkspace`、面板头、页脚、Splitter 同时画边界 |
| 目录选中背景铺满整栏宽度 | 生硬、块状 | `QTreeWidget::item` 使用 0 圆角、0 外边距 |
| 列表行也是满宽矩形 | 内容缺少呼吸感 | 全局规则覆盖了前面已有的 6px 行圆角 |
| 顶部标签、搜索框、下拉和按钮彼此独立 | 工具栏碎片化 | 缺少统一 Toolbar / SegmentedControl 容器 |
| 大量空白直接暴露为纯白面板 | 空而不松弛 | 缺少空状态或内容画布宽度约束 |
| 文本箭头和字符菜单仍存在 | 原生控件感明显 | 尚未建立统一 SVG 图标服务 |

尤其需要注意：`theme.py` 中题库列表样式出现了前后两组规则。后一组将
`FilterNav`、`ProblemList` 和 `KnowledgeTree` 的圆角、边距重置为 0，这会抵消前面的柔和处理。

### 3.2 笔记页

当前优点：

- “空间—笔记列表—阅读/编辑”的三栏信息架构已经成立；
- 阅读与编辑已完成渐进披露；
- 页面级操作比早期版本集中。

主要问题：

| 现象 | 造成的感受 | 根因 |
| --- | --- | --- |
| 三栏由连续竖线切开 | 像文件管理器原型 | 三个 `CardFrame`/Pane 紧贴，Splitter 仅 1px |
| 左栏内部仍有输入框、蓝色满宽列表项和底边线 | 控件堆叠感重 | 原生列表绘制与卡片边框混用 |
| 右侧阅读区铺满灰白背景 | 阅读焦点不集中 | 缺少居中的阅读画布与最大内容宽度 |
| 空笔记状态只有文字 | 大面积空白显得未完成 | 空状态缺少图标、说明和下一步动作层级 |
| 顶部“更多”“编辑笔记”等动作不在统一工具栏表面内 | 顶部节奏松散 | PageHeader 与详情 Toolbar 未形成组件 |

### 3.3 全局组件

当前 `theme.py` 已有颜色 Token，但 Token 仍偏“属性集合”，缺少更高层的语义：

- 只有 `bg / sidebar / card / border`，不足以区分画布、外壳、面板、悬浮层、凹陷输入和阅读画布；
- 只有一个 `border`，导致普通分隔线、输入边框、强调边界同样清晰；
- 颜色可以统一，但无法保证不同页面拥有一致的表面关系；
- 尺寸与圆角散落在 QSS 和页面代码里，不便于整体调整。

当前 `CardFrame` 只有一种形态：白底、1px 边框、8px 圆角、16px 内边距。它同时承担页面卡片、工作区面板、表单分组、空状态等多种职责，最终会出现“所有东西都像同一种方框”。

## 4. 目标视觉语言

建议把下一阶段视觉关键词固定为：

- 自然：组件边界不抢内容；
- 柔和：低对比表面、内缩选中、连续曲率；
- 安静：减少纯黑、粗字、强蓝和重复分割线；
- 清楚：柔和不等于模糊，焦点、层级和状态必须明确；
- 稳定：不同缩放和窗口尺寸下不变形、不跳动；
- 高效：保留桌面端信息密度和键盘操作。

### 4.1 表面层级

建议从当前三层扩展为六个语义表面：

| Token | 建议浅色值 | 用途 |
| --- | --- | --- |
| `canvas` | `#F3F6FA` | 应用最底层背景 |
| `shell` | `#F8FAFD` | 侧栏、模块外壳 |
| `surface` | `#FFFFFF` | 主内容、阅读画布 |
| `surface_subtle` | `#F7F9FC` | 目录栏、次级面板 |
| `surface_hover` | `#F2F5FA` | 悬停 |
| `surface_selected` | `#E8F0FF` | 选中 |

边界拆为：

| Token | 建议值 | 用途 |
| --- | --- | --- |
| `divider` | `#EEF1F5` | 行分隔、栏间弱分隔 |
| `border` | `#E2E7EF` | 输入框、按钮、独立卡片 |
| `border_strong` | `#CCD5E3` | 焦点外的少数强调边界 |
| `focus_ring` | `#7EA6FF` | 键盘与输入焦点 |

文本拆为：

- `text_primary`: `#1F2329`
- `text_secondary`: `#5F6673`
- `text_tertiary`: `#8A93A3`
- `text_disabled`: `#AAB1BC`

这些数值只是原型起点，最终需在真实显示器上人工确认，不应直接当作最终品牌规范。

### 4.2 曲率层级

圆角应当有包含关系，而不是所有组件统一加大：

| 层级 | 建议圆角 | 组件 |
| --- | --- | --- |
| 微型 | 4-6px | 标签、状态点、进度块 |
| 控件 | 8px | 输入框、普通按钮、图标按钮 |
| 行项目 | 8-10px | 树节点、列表行、菜单项 |
| 小容器 | 10-12px | 工具栏、搜索组、空状态 |
| 工作区 | 14px | 题库/笔记主体、表单大组 |
| 应用外壳/浮层 | 16px | 内层主壳、对话框、弹出面板 |

圆角增加时必须同时增加内边距或外边距。只有圆角、没有留白，会显得像“削掉四个角的矩形”，仍然生硬。

### 4.3 间距与密度

建议建立 `UiMetrics`，避免页面继续硬编码：

- 页面外边距：20 / 24px；
- 页面区块间距：16px；
- 面板内边距：16px；
- 工具栏内边距：6 / 8px；
- 栏间视觉沟槽：8 / 12px；
- 标准列表行：40px；
- 双行列表项：56 / 64px；
- 输入和按钮：36px；
- 紧凑图标按钮：32px；
- 行内元素间距：8px；
- 标题与说明间距：4px。

长列表可以提供“舒适 / 紧凑”两档密度，但第一轮不必开放用户设置，只需把数值集中管理。

### 4.4 字体与字重

- 页面标题保留 600，不使用过粗的 700；
- 面板标题使用 600，但减少同时出现的粗体标题数量；
- 列表主标题使用 500 或 600，元数据使用普通字重；
- 面包屑、说明、计数优先使用次级文字色，不默认使用蓝色；
- 蓝色仅表示可点击、当前选择或主要状态；
- 中文行高需显式留足，避免文字在 34px 行高内显得拥挤。

## 5. 关键技术方法

### 5.1 将主题从“颜色表”升级为“语义 Token + 尺寸 Token”

目标文件：

- `apps/windows/src/yancuo_win/ui/theme.py`
- 可新增 `apps/windows/src/yancuo_win/ui/metrics.py`

建议：

1. 扩展 `ThemeTokens`，增加 `canvas/shell/surface_subtle/divider/focus_ring`；
2. 用集中常量管理 radius、height、spacing 和 content width；
3. 清理同一选择器在 QSS 中多次声明、后者覆盖前者的问题；
4. 减少 `QWidget`、`QPushButton` 等全局宽泛规则，更多使用稳定 `objectName`；
5. 给暗色主题保留同样的表面层级，而不是只把颜色取反。

### 5.2 不只依赖 QSS 绘制圆角列表

Qt 的 `QTreeWidget::item` 和 `QListWidget::item` 使用 QSS 时，选中背景容易铺满整行，复杂情况下圆角和内边距也不稳定。

建议新增统一的 `SoftItemDelegate(QStyledItemDelegate)`：

- 在单元格矩形内缩 4px 后绘制 hover / selected 背景；
- 使用抗锯齿圆角矩形；
- 焦点状态绘制克制的外环，而不是虚线框；
- 保留键盘选择、可访问性和原生滚动行为；
- 用参数区分单行树节点、双行列表项和紧凑列表。

它应优先用于：

- `KnowledgeTree`
- `FilterNav`
- `NoteCollectionList`
- `NoteList`
- 复习计划目录与资料列表

对于已经使用 `setItemWidget()` 的复杂题目行，应由行组件自己绘制背景，不再让底层 `QListWidgetItem` 同时绘制一层。

### 5.3 建立多种 Surface，而不是继续复用一种 CardFrame

建议保留 `CardFrame` 兼容旧页面，并新增：

- `SoftSurface`：无边框或极弱边框的柔和表面；
- `WorkspaceSurface`：14px 圆角的页面主体；
- `InsetPane`：用于目录栏、筛选栏的灰白内嵌面板；
- `ReadingCanvas`：白色、限定最大宽度的阅读画布；
- `FloatingSurface`：仅用于菜单、对话框、Toast，可有轻微阴影。

不建议给所有表面增加阴影。Qt Widgets 没有 CSS `box-shadow`，`QGraphicsDropShadowEffect` 在长列表和大区域上成本较高，也容易让文字变糊。阴影只用于少量浮层，主页面层级通过背景差、留白和弱边界实现。

### 5.4 统一 SVG 图标服务

建立一套中性线性 SVG 图标，不复制第三方图标资源：

- 16px：行内、树节点、搜索、更多；
- 20px：工具栏；
- 24px：模块导航；
- 统一 1.75-2px 视觉线宽；
- 图标颜色根据 normal / hover / selected / disabled 状态变化；
- 所有纯图标按钮提供 Tooltip、AccessibleName 和键盘焦点。

应逐步替换：

- `▼`、`▾`、`...`
- `+ 新建`
- 文本模拟的返回箭头
- 平台差异明显的 Qt StandardPixmap

第一轮只替换高频页面，避免一次性更换导致不可控的资源问题。

### 5.5 处理 Qt 圆角和子控件裁剪限制

Qt 样式表的 `border-radius` 不一定会自动裁剪所有子控件背景。实施时应遵循：

- 外层圆角容器的子面板使用同色背景，避免边角露白；
- 需要真实裁剪的少数组件可使用 `paintEvent` 绘制背景；
- 不在滚动列表每一行使用昂贵的遮罩或阴影；
- Splitter 不再用 1px 深色手柄表现分栏，改为 8-12px 透明沟槽或极弱分隔；
- 对话框圆角受 Windows 原生窗口边框限制，优先保证内容区，而不是强行制作无边框窗口。

### 5.6 微交互

Qt Widgets 可使用短时长 `QPropertyAnimation`，但必须克制：

- Hover 颜色：80-120ms；
- 面板展开/折叠：140-180ms；
- Toast：淡入/停留/淡出；
- 页面切换默认不做大幅滑动；
- 尊重系统“减少动画”偏好；若无法读取，至少提供全局关闭开关；
- 不给长列表滚动、树节点逐行加入动画。

柔和感主要来自静态层级，动画只是补充。

## 6. 页面改造蓝图

### 6.1 题库

建议结构：

```text
页面标题 / 操作
柔和工具栏（视图切换 + 范围 + 搜索 + 主动作）
┌──────────────── WorkspaceSurface ────────────────┐
│ InsetPane：知识目录   12px 沟槽   主列表 Surface │
│ 内缩树节点                         内缩题目行      │
└─────────────────────────────────────────────────┘
```

具体调整：

1. 将“浏览题库 / 处理中”改为真正的轻量分段控件或安静页签；
2. 把搜索模式、范围、搜索输入整合为一个 Toolbar 表面；
3. 工作区保留一个外层轮廓，内部不再重复画完整边框；
4. 左侧目录采用 `surface_subtle`，右侧主列表采用 `surface`；
5. 树节点左右内缩 6-8px，选中背景圆角 8px；
6. 题目行使用 12-16px 水平内边距，分隔线不贯穿全部宽度；
7. 标签降低对比度，只让优先级或异常状态保留语义色；
8. 空列表显示“当前范围暂无题目”和一个上下文操作，不暴露整块纯白；
9. “新建 / 管理”使用图标和菜单，不再依赖字符箭头。

### 6.2 笔记

建议结构：

```text
页面标题 / 操作
┌────────────── WorkspaceSurface ──────────────────┐
│ InsetPane       InsetPane        ReadingCanvas   │
│ 笔记空间   10px 笔记列表    12px 阅读/编辑内容   │
└─────────────────────────────────────────────────┘
```

具体调整：

1. 三栏仍保留，但用表面差和沟槽替代连续竖线；
2. 左栏合集节点采用内缩圆角选择态，目录图标统一；
3. 中栏笔记项使用双行组件：标题、摘要/修改时间、状态；
4. 搜索与模式切换合并为紧凑工具区；
5. 阅读区使用最大宽度约 840-920px 的居中画布；
6. 大屏下画布两侧留白，不让正文和公式无限拉宽；
7. 阅读页工具栏固定为“状态—上下文操作—主操作”的稳定结构；
8. 无内容笔记显示清晰空状态，并提供“编辑笔记”主动作；
9. 编辑器内部继续渐进披露，减少同时出现的 CardFrame 数量。

### 6.3 应用外壳

1. 在 Windows 客户区内建立 8-12px 的视觉缓冲，不让主页面紧贴边缘；
2. 侧栏使用极浅冷灰或淡蓝灰，与主画布形成柔和层级；
3. 当前导航项采用内缩圆角背景，不占满侧栏；
4. 品牌区、一级导航和底部统计之间使用留白，不用多条分隔线；
5. 折叠按钮改为标准图标按钮并弱化边框；
6. 顶部模块标题与页面标题避免重复争夺视觉焦点。

## 7. 实施阶段

### 阶段 0：视觉基线与原型，不进入业务页

目标：先验证方向，避免再次全局修改后回滚。

- 固定 1920×1080、1366×768、125% 缩放的题库和笔记截图；
- 建立一个只使用假数据的 `VisualSandbox`；
- 同屏展示按钮、输入框、树节点、列表行、面板、标签和空状态；
- 制作 A/B 两种曲率和表面方案；
- 人工确认后冻结 Token v2。

交付物：

- 视觉基线截图；
- Token 表；
- 组件原型截图；
- 选定方案记录。

### 阶段 1：主题基础设施

- 扩展语义颜色 Token；
- 新增尺寸/间距/圆角 Token；
- 清理重复 QSS 规则；
- 实现 `SoftItemDelegate`；
- 建立 SVG 图标加载和状态着色；
- 保持旧组件可用，新增组件不直接替换全局。

验收：VisualSandbox 中所有状态完整，亮/暗主题均可读。

### 阶段 2：应用外壳与公共组件

- 外壳、侧栏、PageHeader；
- Button、IconButton、SearchField、SegmentedControl；
- WorkspaceSurface、InsetPane、ReadingCanvas；
- EmptyState、Menu、Toast、Dialog。

## 9. 验收标准

### 9.1 视觉

- 第一眼不再像由多个 Qt 原生表格拼接而成；
- 主要页面最多保留一个清晰外层工作区轮廓；
- 列表与树选中态均内缩、圆角，不铺满整个分栏；
- 分栏主要依靠表面差和留白，连续深色竖线显著减少；
- 主要按钮仍清晰，但页面不存在多块高饱和蓝色竞争；
- 标题、正文、说明和元数据具有稳定字重层级；
- 空白区域有阅读画布或空状态承接；
- 图标风格、大小和颜色统一。

### 9.2 功能

- 不改变服务层调用、数据库字段和同步协议；
- 题库筛选、树展开、滚动和选择状态不丢失；
- 笔记三栏、合集、搜索、阅读和编辑不回退；
- 键盘操作与焦点可见；
- 暗色主题无低对比文字或刺眼边框；
- 高 DPI 下图标和圆角无明显锯齿；
- 大列表滚动无可感知卡顿。

### 9.3 验收方式

每个试点页面需要：

1. 同尺寸改造前后截图；
2. 100%、125%、150% 缩放截图；
3. 亮色/暗色截图；
4. 空、少量、长列表三种数据状态；
5. 鼠标 hover、selected、focus、disabled 状态；
6. 对应页面单元测试；
7. 完整 Ruff、compileall 和单元测试。

## 10. 风险与回滚

| 风险 | 处理 |
| --- | --- |
| QSS 全局规则影响旧页面 | 新组件使用专属 objectName；按页面逐步接入 |
| 圆角容器子控件露白 | 同色子表面或自绘背景，不滥用遮罩 |
| Delegate 影响文字/图标布局 | 先在 VisualSandbox 和单一树控件试点 |
| 阴影导致重绘变慢 | 只允许浮层使用，不用于列表项和大工作区 |
| 视觉变柔但信息密度下降 | 保留 40/56px 两档行高，实测长列表 |
| 暗色主题滞后 | Token v2 同时定义亮暗色，不在最后补丁式适配 |
| 多轮改造再次碎片化 | 每阶段只从公共组件向页面迁移，禁止页面局部硬编码 |

回滚策略：

- Token v2 与旧 Token 并存一个迁移周期；
- 新 Surface 和 Delegate 均为显式接入；
- 题库完成验证后再迁移笔记；
- 不用单次全局 QSS 替换覆盖全部页面；
- 每阶段保持独立提交，可按组件或页面回退。

## 11. 实施前需要确认的视觉决策

正式编码前只需确认以下四项：

1. 外壳曲率：偏克制的 12/14px，还是更柔和的 14/16px；
2. 页面密度：保持当前密度，还是增加约 8%-12% 留白；
3. 选中底色：继续使用淡蓝，还是更中性的蓝灰；
4. 题库试点通过后，是否优先迁移笔记而不是录题页。

建议默认方案：

- 控件 8px、行项目 10px、工作区 14px、浮层 16px；
- 留白增加约 8%，不显著降低信息密度；
- 保留低饱和淡蓝选中态；
- 实施顺序为题库 → 笔记 → 录题。
