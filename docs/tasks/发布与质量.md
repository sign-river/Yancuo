### REL-005 · 对象库路径边界加固

- 状态：已完成
- 来源：全部可执行任务完成后的主动安全审计。
- 风险：资源相对路径来自数据库、同步或导入记录；旧 `ObjectStore.resolve` 只拼接并解析路径，没有确认最终目标仍位于内容寻址对象库。恶意或损坏记录可能借助 `..`、绝对路径、驱动器路径或符号链接把读取重定向到对象库之外，并被预览、导出或 AI 图片上下文读取。
- 修复：统一拒绝空路径、NUL、绝对路径、驱动器/ADS 冒号和解析后越出对象库的目标；`objects/` 前缀与旧的无前缀相对格式均限制在同一 resolved root 内，指向根目录本身也被拒绝。
- 验证：覆盖正常跨端哈希对象、父目录穿越、伪造 `objects/../../`、Windows 绝对路径、空路径和目录目标，并回归资源服务、增量同步和题目讨论裁剪读取。

### REL-006 · 内容寻址对象写入完整性

- 状态：已完成
- 来源：对象库路径边界修复后的连续安全审计。
- 风险：旧写入流程在目标哈希路径已存在时直接信任文件，损坏或被替换的对象会继续作为正确原图使用；新对象也直接复制到最终文件名，进程中断可能留下可见的半写入文件。
- 修复：复用既有对象前重新计算 SHA-256 并拒绝哈希不符；新对象先写入同目录唯一临时文件、刷新并 `fsync`、复核哈希后再原子替换到最终路径。写入目标、父目录或既有目标为越界符号链接时拒绝操作，临时文件在所有失败路径清理。
- 验证：覆盖损坏的既有哈希路径拒绝、临时写入后内容一致、无临时文件残留，以及录题和资源服务回归。

### REL-007 · 外部编辑工作区读取边界

- 状态：已完成
- 来源：外部输入面连续安全审计。
- 风险：工作区导入会读取用户选择目录中的 manifest、题目 Markdown、元数据和资源引用；旧流程允许题目目录/文件符号链接，资源文件名也可包含父目录穿越，且文本读取没有单文件或题目目录数量上限。
- 修复：manifest、元数据和 Markdown 统一使用带 UTF-8、符号链接及大小限制的读取器；`problems/`、题目目录、`assets/` 和资源文件拒绝符号链接，资源名通过安全相对路径解析；题目目录总数限制为 10000。
- 验证：覆盖正常导出—导入—审核、缺失资源、无效 manifest，以及指向工作区外既有文件的 `../../` 资源引用拒绝。

### REL-008 · 增量同步批次输入预算

- 状态：已完成
- 来源：云端与本地同步输入面连续安全审计。
- 风险：GitHub 批次索引中的远端 `asset_name` 曾直接参与本地临时路径拼接；本地文件夹与 GitHub 的 JSONL 批次读取也缺少文件大小、记录数和设备/批次数量预算，损坏或恶意同步目录可造成路径越界尝试或内存/磁盘消耗。
- 修复：GitHub 只接受固定 `operations.jsonl` 资源名并始终下载到本地固定文件名，同时校验 SHA-256 格式、批次 ID 去重、索引/文件/记录上限与 UTF-8；本地文件夹通道拒绝 `ops.jsonl` 符号链接，并使用相同量级的设备数、文件大小、记录数和编码预算。
- 验证：覆盖 GitHub 正常推拉、篡改哈希、错误索引、恶意 `../../` 资源名不触发下载，以及本地 JSONL 非对象行、超限文件和非法 UTF-8。

### REL-009 · 单资源存储预算

- 状态：已完成
- 来源：资源耗尽风险连续审计。
- 风险：图片/附件在计算哈希和复制前没有统一单文件大小限制，手动选择或文件夹扫描到异常大文件时会长时间占用磁盘 I/O，并可能在预览、导出或 AI 上下文阶段进一步放大内存占用；空文件也会进入内容寻址库成为无效资源。
- 修复：对象库作为所有原图和派生资源的统一写入边界，在哈希前拒绝空文件和超过 128 MiB 的单文件；所有录题、笔记、分享包、同步附件和派生题图自动继承同一预算。
- 验证：覆盖空文件、超限文件、正常原图、派生资源和录题/资源服务回归。

### REL-010 · 本地文件夹云元数据完整性

- 状态：已完成
- 来源：可移动盘、网络盘和同步盘输入面连续安全审计。
- 风险：`repository.json`、`latest.json`、`release.json` 与 `devices.json` 来自可被其他进程修改的共享目录；旧流程无统一大小/编码/JSON 类型限制，release、asset 和 device 列表也无数量预算，部分写入直接覆盖目标文件，异常中断可能留下半写入元数据。
- 修复：共享 JSON 元数据统一拒绝符号链接、超 8 MiB、非法 UTF-8/JSON 和错误根类型；release、单 release 资源及设备列表分别限制为 10000 项。同步清单和设备列表使用同目录唯一临时文件、刷新、`fsync` 和原子替换，失败后清理临时文件；设备 ID 通过安全路径组件校验。
- 验证：覆盖正常清单往返、原子写入无临时文件残留、超限读取拒绝、不安全设备 ID 拒绝，以及云备份、资料合并与增量同步回归。

### REL-011 · AI 审核批量决策查询去重

- 状态：已完成
- 来源：全部可执行任务完成后的性能与冗余审计。
- 问题：AI 补全审核列表刷新时已经取得每条建议的并发状态，但“全部采用”仍按字段重复调用展示查询；同一建议含多个字段时会重复解析审核载荷并访问题目状态，形成随字段数增长的 N+1 查询。
- 优化：列表行复用刷新阶段取得的状态快照，批量决策直接判断该快照并继续跳过冲突字段；最终刷新仍重新读取服务端状态，保持界面与实际审核项一致。
- 验证：新增批量决策查询次数回归，完整 Windows 单元测试 `409 passed`，Ruff 与 Python 编译检查通过。
