### REL-005 · 对象库路径边界加固

- 状态：已完成
- 来源：全部可执行任务完成后的主动安全审计。
- 风险：资源相对路径来自数据库、同步或导入记录；旧 `ObjectStore.resolve` 只拼接并解析路径，没有确认最终目标仍位于内容寻址对象库。恶意或损坏记录可能借助 `..`、绝对路径、驱动器路径或符号链接把读取重定向到对象库之外，并被预览、导出或 AI 图片上下文读取。
- 修复：统一拒绝空路径、NUL、绝对路径、驱动器/ADS 冒号和解析后越出对象库的目标；`objects/` 前缀与旧的无前缀相对格式均限制在同一 resolved root 内，指向根目录本身也被拒绝。
- 验证：覆盖正常跨端哈希对象、父目录穿越、伪造 `objects/../../`、Windows 绝对路径、空路径和目录目标，并回归资源服务、增量同步和题目讨论裁剪读取。

### REL-006 · 内容寻址对象写入完整性

- 状态：已完成
- 来源：对象库路径边界修复后的连续安全审计。
- 风险：旧写入流程在目标哈希路径已存在时直接信任文件，损坏或被替换的对象会继续作为正确原图使用；新对象也直接复制到最终文件名，进程中断可能留下可见的半写入文件。
- 修复：复用既有对象前重新计算 SHA-256 并拒绝哈希不符；新对象先写入同目录唯一临时文件、刷新并 `fsync`、复核哈希后再原子替换到最终路径。写入目标、父目录或既有目标为越界符号链接时拒绝操作，临时文件在所有失败路径清理。
- 验证：覆盖损坏的既有哈希路径拒绝、临时写入后内容一致、无临时文件残留，以及录题和资源服务回归。

### REL-008 · 增量同步批次输入预算

- 状态：已完成
- 来源：云端与本地同步输入面连续安全审计。

### REL-009 · 单资源存储预算

- 状态：已完成
- 来源：资源耗尽风险连续审计。
- 风险：图片/附件在计算哈希和复制前没有统一单文件大小限制，手动选择或文件夹扫描到异常大文件时会长时间占用磁盘 I/O，并可能在预览、导出或 AI 上下文阶段进一步放大内存占用；空文件也会进入内容寻址库成为无效资源。

- 验证：覆盖空文件、超限文件、正常原图、派生资源和录题/资源服务回归。

### REL-011 · AI 审核批量决策查询去重

- 状态：已完成
- 来源：全部可执行任务完成后的性能与冗余审计。
- 问题：AI 补全审核列表刷新时已经取得每条建议的并发状态，但“全部采用”仍按字段重复调用展示查询；同一建议含多个字段时会重复解析审核载荷并访问题目状态，形成随字段数增长的 N+1 查询。
- 优化：列表行复用刷新阶段取得的状态快照，批量决策直接判断该快照并继续跳过冲突字段；最终刷新仍重新读取服务端状态，保持界面与实际审核项一致。
- 验证：新增批量决策查询次数回归，完整 Windows 单元测试 `409 passed`，Ruff 与 Python 编译检查通过。

### REL-012 · 朋友分享包完整性与输入预算

- 状态：已完成
- 来源：外部归档输入面连续安全审计。
- 风险：`.gmshare` 导入只校验 checksum 表中主动列出的文件，缺失条目不会失败，因此题目载荷、资源索引或额外文件可能绕过完整性覆盖；题目 JSONL 也会一次性读入内存，且 manifest、记录数、资源引用数和单行大小缺少一致预算。
- 修复：checksum 表必须以规范相对路径完整且唯一地覆盖包内除自身外的全部文件，摘要必须为 SHA-256；题目 JSONL 改为逐行限长读取，题目与资源引用均限制为 10000 条，并交叉核对 manifest、资源索引和题目引用数量。manifest、题目记录与资源索引同时校验 JSON 根类型。
- 验证：覆盖正常脱敏导入和溯源去重、题目载荷被篡改、checksum 覆盖缺失、归档安全边界；完整 Windows 单元测试 `411 passed`，Ruff 与 Python 编译检查通过。

### REL-013 · AI 网络响应内存预算

- 状态：已完成
- 来源：外部网络输入面连续安全审计。
- 风险：OpenAI 兼容接口的普通 JSON、非 SSE 回退和流式 SSE 响应此前都没有累计读取上限；配置错误、异常代理或恶意兼容服务可持续返回数据并耗尽客户端内存，HTTP 错误正文也会先完整读取再截断展示。
- 修复：普通与流式成功响应统一限制为 16 MiB，SSE 在逐行处理时累计字节并立即终止超限连接；错误正文最多读取 4 KiB。响应解析、密钥脱敏、瞬态重试和已输出流式内容不自动重试的语义保持不变。
- 验证：新增普通 JSON 与 SSE 超限拒绝回归，完整 Windows 单元测试 `413 passed`，Ruff 与 Python 编译检查通过。

### REL-014 · GitHub 认证源站与下载预算

- 状态：已完成
- 来源：云端网络边界连续安全审计。
- 风险：GitHub Release 返回的上传/下载 API URL 会携带 Bearer 令牌继续请求，但此前未限制目标源站；异常 API 响应可把令牌带到第三方地址。GitHub JSON 响应和 Release 附件实际下载量也没有读取上限，远端声明大小不能单独作为可信预算。
- 修复：GitHub API 基址强制为 HTTPS，所有认证请求仅允许同 API 源站；官方 `api.github.com` 额外只放行 `uploads.github.com` 上传源站。JSON 响应限制为 8 MiB、错误正文限制为 4 KiB；下载同时校验声明大小并逐块执行 2 GiB 实际上限，超限删除部分文件。
- 验证：覆盖跨源认证 URL 拒绝、JSON 超限、附件实际下载超限与清理，以及 GitHub Release/Operation 同步回归；完整 Windows 单元测试 `416 passed`。

### REL-015 · CloudBase 网关传输边界

- 状态：已完成
- 来源：云端网络边界连续安全审计。
- 风险：CloudBase 网关配置和返回的签名存储地址接受明文 HTTP；网关 JSON 和对象下载会一次性无界读入内存，上传也没有统一文件预算。异常网关或存储端可造成令牌/资料明文传输、内存耗尽或超量落盘。
- 修复：网关与签名存储 URL 强制为无内嵌凭据的 HTTPS；网关 JSON 限制为 8 MiB、错误正文限制为 4 KiB，上传与下载统一限制为 512 MiB。下载改为逐块写入并累计实际字节，所有失败路径删除部分文件，并通过 provider capability 公布相同上限。
- 验证：覆盖明文网关拒绝、网关响应超限、对象实际下载超限与部分文件清理，以及 CloudBase 工厂和健康检查回归；完整 Windows 单元测试 `419 passed`。

### REL-016 · HTTPS 重定向凭据隔离

- 状态：已完成
- 来源：认证网络请求连续安全审计。
- 风险：Python 默认 HTTP 重定向会复制 `Authorization` 等请求头；AI、GitHub 或 CloudBase 的服务端若返回跨源 30x，可把 API Key、Bearer 令牌或存储授权头转发到第三方地址，HTTPS 到 HTTP 的降级跳转也会被自动跟随。
- 修复：新增统一安全 HTTPS 打开器。认证 API 默认只跟随同源 HTTPS 重定向；GitHub 附件下载因官方对象存储跳转需要可选择允许跨源 HTTPS，但在跳转前移除 Authorization、Cookie、代理授权与 API Key 头。所有 HTTP 降级跳转一律拒绝，AI、GitHub 和 CloudBase 的网络入口统一接入。
- 验证：覆盖同源保留认证、默认拒绝跨源、必要跨源剥离认证和 HTTPS 降级拒绝，并回归三个 provider；完整 Windows 单元测试 `423 passed`。
