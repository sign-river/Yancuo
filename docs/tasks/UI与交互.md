## P0 · 发布前收口

### UI-123 · 修复题库展开项销毁后的延迟尺寸同步

- 状态：已完成
- 来源问题：`ISSUE-20260731-009`
- 现象：刷新或回收题库展开项后，数学内容高度回调仍持有已删除的 `QListWidgetItem`，导致点击展开时反复输出 PySide6 `Internal C++ object ... already deleted` 警告。
- 目标：延迟回调仅持有稳定题目 ID，触发时重新查找当前项；旧项或旧控件已失效时静默退出。
- 验收：展开、折叠、滚动回收和刷新题库不产生已删除对象警告，当前展开项仍能按内容高度更新。
- 结果：尺寸回调改为捕获稳定题目 ID，触发时重新查询当前项并核对当前控件实例；已回收或已替换的行会直接忽略。

### UI-004 · 修复题目内 AI 对话资源排序报错

- 状态：已完成
- 来源问题：`ISSUE-20260730-002`
- 现象：在题目详情发送 AI 讨论消息后失败，界面显示 `type object 'Asset' has no attribute 'sort_order'`。
- 初步边界：资源排序逻辑引用了 `Asset` 不存在的类属性；实施时必须确认正确的题目资源关系和稳定顺序，不能只吞掉异常。
- 验收：无原图、单原图和多原图题目均能创建并继续对话；授权携带原图时上下文顺序稳定；失败消息可重试且不丢失用户提问。
- 结果：仅选择题目的 `original` 资源并按 `created_at + id` 确定性排序，授权后可按序携带多张原图；无有效原图时安全退回纯文本。重试相同失败提问会复用原消息并清除错误，不产生重复提示。

### UI-005 · 修复识别缓存命中后的科目与章节恢复

- 状态：已完成
- 来源问题：`ISSUE-20260730-007`
- 现象：新鲜 AI 识别可以得到分类信息，但命中本地识别缓存后，确认页的科目和章节显示“未指定”。
- 实施要求：缓存路径必须经过与新鲜识别相同的结果规范化、已有目录匹配和新章节提案流程；不能依赖仅存在于网络请求回调中的临时状态。
- 验收：同一图片首次识别与缓存命中的标题、科目、章节及分类提案一致；目录已删除或变化时安全回退为重新匹配/待确认，而不是写入失效 ID。
- 结果：缓存升级为向后兼容的 v2 信封，保存规范化字段、不确定项、区域和受控结构诊断，命中后重走相同候选创建与目录校验；目录提示变化会自然改变缓存键，失效章节 ID 被清除并标记待确认。

### UI-006 · 研究并修复内容渲染容器大片空白

- 状态：已完成
- 来源问题：`ISSUE-20260730-005`
- 现象：题库展开项、题目详情、AI 确认阅读预览和编辑字段等多个公式/PDF 式内容区域，在实际内容结束后仍保留大面积空白。
- 研究要求：先区分空白来自 PDF/分页生成、HTML/CSS 的 `min-height`/视口单位、Qt Web 容器尺寸策略，还是外层布局 stretch；不预设根因。
- 实施要求：公共修复优先落在共享渲染组件，避免四个页面分别硬编码高度。
- 验收：短题内容高度贴合且保留合理内边距；长题、公式、图片和滚动不被裁切；题库展开、题目详情、AI 阅读预览与编辑字段四个场景均有回归覆盖。
- 结果：确认根因是无窗口 `QWebEnginePage` 的零宽视口让 `scrollHeight` 按逐字换行膨胀，叠加整页 PDF 和外层 stretch。共享阅读器现固定 794 CSS px 测量宽度，并提供短内容贴合、长内容达到上限后内部滚动的自适应模式；四个目标场景已统一接入。

### UI-007 · 修复 AI 录题步骤条文字挤压

- 状态：已完成
- 来源问题：`ISSUE-20260730-006`
- 现象：“上传图片—后台处理—确认结果”步骤条在当前窗口宽度下把编号和文字压缩到不可读。
- 实施要求：步骤节点采用内容感知的最小宽度，连接线只占剩余空间；窄窗口可缩短辅助文字或切换紧凑布局，但不能裁切当前步骤名称。
- 验收：760px、1366px 和 1920px 宽度下三步文字均可辨认，当前/完成/待进行状态清晰，读屏名称保持完整。
- 结果：节点最小宽度由实际文字度量加内边距确定，使用不可换行的 Minimum 尺寸策略；连接线最小仅 8px 并独占伸缩权重。步骤条高度调整为 44–48px，三档目标宽度下文字和当前态边框均完整。

### UI-008 · 复核 AI 识别阶段耗时

- 状态：已完成
- 来源问题：`ISSUE-20260730-009`
- 目标：重新确认图片识别慢在本地编码、排队、远端请求、结构化解析、分类匹配还是界面等待，不把单次网络耗时直接归因于 UI。
- 采样范围：缓存未命中/命中、单图/多图、首次请求/重试，并记录 Provider 是否返回 token 与服务端计时。
- 验收：输出可重复的隔离采样步骤和阶段耗时表；缓存命中不得发起远端请求；只有证据指向本地瓶颈时才进入优化实现。
- 隔离复测：在仓库根目录执行 `python tools/ai_intake_timing.py`。命令使用带标记的系统临时资料和本机 OpenAI 兼容 HTTP 服务，依次运行单图未命中、同图命中、双图合并未命中及首请求 503 后自动重试；结束后自动清理资料。
- 本机阶段表（毫秒，单次诊断样本）：

  | 场景 | 排队 | 编码 | 请求/等待 | 解析 | 校验+写入 | 分类匹配 | UI 等待 | Provider 调用 |
  | --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
  | 单图未命中 | 26.9 | 0.1 | 144.9 | 0.0 | 6.8 | 5.9 | 0.8 | 1 |
  | 单图缓存命中 | 17.9 | — | — | — | 2.3 | 2.8 | 0.7 | 0 |
  | 双图合并未命中 | 19.4 | 0.3 | 1.3 | 0.0 | 2.7 | 3.3 | 1.0 | 1 |
  | 单图自动重试 | 16.9 | 0.1 | 612.4 | 0.0 | 10.0 | 2.6 | 0.8 | 2 |

- 结论：缓存命中经调用计数断言确认没有请求 Provider；模拟 Provider 返回的 token 用量和 `Server-Timing`/处理毫秒均已记录。重试增加的主要是请求等待，本地编码、解析、分类和 UI 信号交付均未形成瓶颈，因此本任务只补齐观测和采样能力，不进行缺乏证据的性能改写。

### UI-001 · 详情与数据结果可访问性

- 状态：已完成
- 来源问题：历史 UI 任务收口
- 范围：题目详情、导入导出结果、云端恢复/合并与同步结果。
- 实施要求：检查 Tab 顺序、焦点可见性、快捷键提示、读屏名称和错误恢复入口。
- 验收：QTest 覆盖核心焦点链；真实 Windows UI Automation 至少抽查一个详情页和一个结果窗口。
- 结果：题目详情补齐可读的返回、正文/PDF 阅读器、AI 对话及管理动作名称，`Alt+Left` 返回快捷键和显式焦点链；待确认变更的列表、差异、不确定项及动作也有稳定读屏名称和 Tab 顺序。导入、导出、备份恢复、云端资料恢复/合并及增量同步统一使用可访问结果窗口，摘要与只读详情分离，失败时提供明确“重新尝试”入口。
- UI Automation 抽查：使用 `python tools/accessibility_probe.py --surface detail|result` 启动真实 Qt 控件，并通过 Windows UI Automation 读取控件树。详情页可发现并聚焦返回、编辑、前后题及“题目正文与解析”；结果窗口可发现摘要、可复制详情、“重新尝试”和“关闭操作结果”。

### UI-002 · 低风险信息提示审计

- 状态：已完成
- 范围：剩余 `QMessageBox.information`。
- 实施要求：短小、可恢复、不要求记住路径或明细的成功反馈可迁移为 Toast；路径、合并明细、异步任务完成和高风险结果必须保留可停留对话框。
- 验收：列出保留与迁移清单；迁移场景有回归测试。
- 迁移清单：题库/批量操作的未选择提示、空导出、对象已删除、云端无可恢复/可合并内容及清空回收站成功改为全局 Toast；作答图片/内容和区域框选的前置提示改为当前流程内联状态；Mock、无需令牌和 Faro 连接成功改为设置页状态反馈；任务中心的未选择/已有任务运行改为摘要区状态。
- 保留清单：主窗口和任务中心的 AI 异步任务完成仍保留可停留对话框，以便记住任务与后续审核位置；云服务连接成功继续保留包含 Provider 返回明细的对话框；审核冲突继续要求用户在对话框中选择处理方式。错误、高风险确认和 UI-001 的路径/恢复/合并明细结果窗口不迁移为 Toast。
- 结果：全项目 `QMessageBox.information` 只剩上述四处明确保留项；迁移场景覆盖无题目选择、作答图片/内容缺失、Mock 连接测试和任务未选择，均确认不再打开阻塞消息框。

### UI-108 · AI 录题的表格与题图结构化支持

- 状态：进行中
- 来源问题：`ISSUE-20260730-010`
- 现状：视觉模型虽然可以理解图片中的表格、函数图像、几何图和流程图，但识别结果没有 `table`、`figure` 等一等内容结构。表格只能被写成普通文字或 Markdown 管道语法，而当前阅读器不会把普通 Markdown 转成表格；题图也只保留在整张原图中，正式题干不能在对应位置直接展示。
- 目标：把题目正文从单一文本字段扩展为有序内容块，至少支持文本、公式、表格和题图；旧的 `question_markdown` / `question_latex` 继续作为兼容输入和降级表示。
- 识别要求：
  - AI 为每个内容块返回类型、内容、顺序、来源图片和归一化区域；无法可靠结构化时必须标记不确定项，不能猜造缺失的单元格、图形标注或数据。
  - 表格保存行列、单元格内容及必要的横跨/纵跨信息；公式单元格继续使用明确的 LaTeX 定界和校验规则。
  - 题图从不可变原图按来源区域生成可追溯的派生裁剪附件；原图始终保留，裁剪不得覆盖原图，也不能丢失多图输入顺序。禁止用生成式 AI 重绘题图或表格，以免坐标、标注、数值和几何关系偏离原题。
- 确认与编辑要求：
  - AI 确认页按原顺序预览内容块，允许修正表格单元格、内容块顺序和题图裁剪范围。
  - 用户可以把误识别的表格/题图降级为普通文字或仅保留原图；区域重新识别结果仍须经过采用/保留确认。
  - 正式入库前必须能看出哪些内容来自 AI、哪些字段不确定，不能因视觉预览正常而静默保存错误结构。
- 展示与兼容要求：
  - 题库展开项、题目详情、复习、打印/导出均应在题干对应位置显示表格和题图，不要求用户另开“查看原图”才能完成读题；Word 导出必须输出结构化表格和同一可追溯裁剪图。
  - 数据库迁移、完整快照、工作区导入导出和同步协议需要定义新内容块及派生附件语义；旧题无需一次性迁移，读取时安全降级。
  - Markdown 表格即使作为降级输入，也应有明确的渲染或转结构规则，不能继续以竖线纯文本展示。
- 验收：覆盖简单表格、含合并单元格和公式的表格、坐标图、几何图、单题多图及同图多题；确认页、正式阅读和 Word 导出结果顺序一致；裁剪图清晰且可回溯原图；旧库、快照和旧题读取无回归。
- 已完成：协议、题目 schema、内容块测试向量、兼容字段和 v20 数据库迁移已加入，旧题保持安全降级。
- 剩余：录题确认编辑、题图派生附件、正式阅读/导出/同步全链路与完整场景验收。

### UI-109 · AI 后台完成滑入通知

- 状态：已完成
- 来源问题：`ISSUE-20260730-011`
- 触发条件：AI 图片识别任务从运行中进入“已完成且存在待审核候选”时触发一次；缓存命中后若同样产生待审核候选，也使用相同完成通知。失败、取消或没有可审核结果时使用各自的状态反馈，不伪装成完成。
- 视觉结构：圆角浮层从当前屏幕右侧向左滑入；上方大区域显示“AI 识别完成”及候选数量等简短提示，下方独立一行显示倒计时进度条。组件遵循亮暗主题、柔和 Surface 和统一阴影/圆角规范。
- 倒计时：进度条出现时为满值，随后空缺区域从左向右连续增加，直至归零；归零后浮层自动滑出并销毁。显示时长使用可测试的共享配置，不在页面中散落硬编码。
- 点击行为：用户点击通知主体时立即停止倒计时、关闭通知、激活主窗口，并跳转到该次 AI 任务对应的候选审核/确认结果界面；不能误跳到另一批任务。

### UI-122 · 双栏结果对比自适应缩放

- 状态：已完成
- 来源问题：`ISSUE-20260731-006`、`ISSUE-20260731-014`
- 现象：区域重新识别的原结果与新结果并排显示时，数学内容按单栏预览尺度渲染，导致两栏出现横向滚动条、公式或图片无法完整阅读。
- 目标：双栏及其他可复用的并排对比场景应根据每栏可用宽度自动降低内容缩放，优先完整显示内容；只有缩放到安全下限仍不足时才保留横向滚动。
- 验收：长公式、图片和多段内容在 760px、1366px、1920px 窗口下均优先适应各自对比栏；单栏阅读与用户设置的全局预览缩放不受影响。
- 结果：区域重新识别比较窗口会依据实际较窄一栏的可用宽度，在 50% 至 90% 之间独立计算两栏阅读缩放；不改变全局预览缩放。
- 追加目标：缩放以各栏 PDF 视口实际内容宽度为准，优先缩放到横向滚动条消失；仅当达到可读性下限后仍溢出时才保留横向滚动。

### UI-124 · 区域重新识别候选去重与决策一致性

- 状态：已完成
- 来源问题：`ISSUE-20260731-013`
- 现象：用户对当前候选执行区域重新识别后，待审核候选可能被错误增加为两个；即使在比较窗口选择保留原结果，之后仍可能将两个相同题目分别入库。
- 目标：区域重新识别只产生当前候选的一份临时比较提案，不新建可独立入库的候选；采用新结果覆盖当前候选字段，保留原结果丢弃提案，两种决策后待审核数量均保持不变。
- 验收：对单个候选连续重识别、保留原结果、采用新结果、撤回与确认入库均不会产生重复候选或重复正式题；候选计数、列表顺序和持久化状态一致。
- 结果：区域重新识别始终只作用于原候选；后一次未决提案会显式作废前一次，过期提案无法再写回候选。保留原结果、采用新结果、撤回和入库均不改变候选数量。

### UI-125 · 原图查看器缩放语义修复

- 状态：已完成
- 来源问题：`ISSUE-20260731-015`
- 现象：原图查看器的“重置缩放”恢复到 100% 原始像素比例，常在高分辨率图片上显得异常放大，与用户预期的“恢复适应窗口”不一致。
- 目标：明确区分“适应窗口”和“原始大小”；“重置缩放”恢复为打开时的适应窗口比例，原始大小作为独立明确动作，切换图片后也按当前窗口重新适配。
- 验收：横图、竖图、高分辨率图在打开、缩放、重置、适应窗口和切换上一张/下一张后均无突兀放大；缩放标签准确反映实际比例。
- 结果：重置缩放恢复打开时的适应窗口比例；原始大小成为独立动作。切换图片时按当前画布重新计算适应比例。
