#### 改进计划（2026-08-04 · 免费档“只撑一天”的对策）

- 结论：不是存储（3GB 一天约 36 点），而是 PG 实例开机的 CPU 核时（342 点/核·时）在烧点；免费档 3,000 点/月 ≈ 1 核常驻约 8.8 小时，设计意图是“不用就停”，不是 24/7 常驻。
- A. 自动暂停（零成本，优先验证）：官方能力表写明“关系型数据库：个人版默认开启自动暂停，标准版及以上支持关闭自动暂停”。环境恢复后到 PG 管理→配置页确认免费体验版是否开启；若网关连接池（max 5、idle 20s）使实例永不为空，调低 `PG_POOL_SIZE`/`idleTimeoutMillis` 或空闲断开，让实例能暂停。平时不访问 ≈ 不烧点。
- B. 外部免费 PostgreSQL（零成本，长期正道）：把数据库迁到 Neon/Supabase 免费档（自带自动暂停），CloudBase 只留云函数+云存储，绕开 342 点/核·时地板。改动中等：改 `DATABASE_URL`、TLS（`PG_SSL=verify`+CA）、函数超时适配（免费版云函数超时 3s 且不可改，外网冷启动需实测/保活）。
  - B 实测（2026-08-04，本机直连）：neon.tech / console.neon.tech / supabase.com / app.supabase.com / Supabase 新加坡 pooler:5432 全部 TCP 超时；基线 GitHub/npm/Google 同样超时、腾讯云可达；系统代理未启用（已装 Clash Verge 但本地端口 7897 未监听）。结论：管理外部 PG 控制台需开代理；云函数（腾讯上海机房）到外部 PG 的连通性需环境恢复后实测，风险待验证。
  - 迁移后腾讯侧开销测算（2026-08-04，官方资源点价格）：云函数 0.11108 点/GBs + 13.3 点/万次、HTTP 网关 30 点/万次、身份认证 500 点/万次、云存储容量 3.94 点/GB/天、云存储下载 CDN 流量 210 点/GB。正常个人使用（每月几次备份/恢复、留存几百 MB）约几十点/月；即使留存 1GB + 每月下载 10GB，也约 2,000 点/月，仍低于免费 3,000 点。大头从 PG 常驻 CPU 变成存储容量 + 下载流量，都是按用量走、不用不花。
- C. 付费应急（不解决长期问题）：个人版 19.9 元/月 40,000 点 24/7 只够 11~12 天，仅适合集中验收月。

### SYNC-106 · 多用户 CloudBase 网关与自带云端基础

- 状态：实现完成，真实部署验收并入 SYNC-103 阻塞项
- 来源问题：`ISSUE-20260803-003`
- 目标：为开源发布提供官方托管的多用户 CloudBase 通道，并预留用户切换到自有 CloudBase 环境的配置边界，避免官方免费环境成为唯一容量和带宽来源。
- 官方托管：采用 CloudBase 身份认证和邮箱登录；网关验证身份令牌并从可信 `sub` 派生用户命名空间，客户端提交的 owner 不能越权。不同用户的仓库、清单、批次、锁和存储对象必须强隔离。
- 自带云端：网关地址、环境 ID 和逻辑仓库继续可配置；后续用户可部署同版本网关到自己的 CloudBase。数据库密码、SecretId/SecretKey 和网关签名密钥只存在于服务端密钥配置，客户端只保存用户身份令牌到系统凭据管理器。
- 服务端：实现当前仅有契约的 `yancuo-cloud-gateway`，包括参数化 PostgreSQL 访问、私有对象签名 URL、不可变批次、原子锁、幂等提交、容量预算、限流、孤儿对象回收和可审计错误；不记录令牌或资料正文到日志。
- 首期同步：保持用户显式触发的完整备份和增量推拉；真实环境稳定后再单独评估后台自动同步，不在首次部署时引入静默覆盖风险。
- 验收：至少覆盖两用户交叉访问拒绝、伪造 owner、过期/篡改令牌、重复上传、并发锁、提交中断、对象篡改、容量超限、恢复回滚和用户自有环境配置；真实控制台验收只使用免费额度，人工验证或计费步骤记录后跳过。
- 结果：Node HTTP 网关以 CloudBase `/auth/v1/user/me` 验证普通用户 Access Token，以可信 `sub` 隔离仓库、清单、发布、锁和对象路径，忽略客户端 owner 的授权含义；实现参数化 PostgreSQL、原子锁、不可变发布、一次性上传凭据、私有短期下载 URL、单用户容量/仓库预算和限流。桌面端新增用户名密码登录与 refresh token 轮换，密码不落盘；环境 ID、网关 URL 继续可配，为 BYOC 保留边界。
