### SYNC-106 · 多用户 CloudBase 网关与自带云端基础

- 状态：实现完成，真实部署验收并入 SYNC-103 阻塞项
- 来源问题：`ISSUE-20260803-003`
- 目标：为开源发布提供官方托管的多用户 CloudBase 通道，并预留用户切换到自有 CloudBase 环境的配置边界，避免官方免费环境成为唯一容量和带宽来源。
- 官方托管：采用 CloudBase 身份认证和邮箱登录；网关验证身份令牌并从可信 `sub` 派生用户命名空间，客户端提交的 owner 不能越权。不同用户的仓库、清单、批次、锁和存储对象必须强隔离。
- 自带云端：网关地址、环境 ID 和逻辑仓库继续可配置；后续用户可部署同版本网关到自己的 CloudBase。数据库密码、SecretId/SecretKey 和网关签名密钥只存在于服务端密钥配置，客户端只保存用户身份令牌到系统凭据管理器。
- 服务端：实现当前仅有契约的 `yancuo-cloud-gateway`，包括参数化 PostgreSQL 访问、私有对象签名 URL、不可变批次、原子锁、幂等提交、容量预算、限流、孤儿对象回收和可审计错误；不记录令牌或资料正文到日志。
- 首期同步：保持用户显式触发的完整备份和增量推拉；真实环境稳定后再单独评估后台自动同步，不在首次部署时引入静默覆盖风险。
- 验收：至少覆盖两用户交叉访问拒绝、伪造 owner、过期/篡改令牌、重复上传、并发锁、提交中断、对象篡改、容量超限、恢复回滚和用户自有环境配置；真实控制台验收只使用免费额度，人工验证或计费步骤记录后跳过。
- 结果：Node HTTP 网关以 CloudBase `/auth/v1/user/me` 验证普通用户 Access Token，以可信 `sub` 隔离仓库、清单、发布、锁和对象路径，忽略客户端 owner 的授权含义；实现参数化 PostgreSQL、原子锁、不可变发布、一次性上传凭据、私有短期下载 URL、单用户容量/仓库预算和限流。桌面端新增用户名密码登录与 refresh token 轮换，密码不落盘；环境 ID、网关 URL 继续可配，为 BYOC 保留边界。
