## 默认执行顺序

用户说“按照任务书继续”且没有指定方向时，按以下顺序选择任务：

1. 已经影响数据安全、启动、迁移或现有核心流程的 P0 缺陷。
2. 状态为“就绪”的发布与质量门禁。
3. 状态为“就绪”的 UI 发布前收口。
4. 同步与 Android 中依赖已经满足的任务。
5. 体验增强和明确后置能力。

同一优先级下，优先完成范围更小、验收更明确、能解除后续阻塞的任务。

## 总体边界

- `.ebpack` 完整快照仍是恢复与换机的权威通道，增量同步不能替代快照。
- 正式远端只允许 CloudBase；LocalFolder 仅作离线测试，不再提供 Git 仓库型云端入口。
- 原始上传图片只服务于 AI 识别和用户审核；正式题库、笔记与作答记录只保留结构化内容和读题必需的派生裁剪题图。
- 官方 CloudBase 按互不信任的多用户隔离设计；后续允许高级用户切换到自己的 CloudBase 环境，但客户端永远不携带数据库或云平台管理密钥。
- AI 搜索只发送本地有限候选，禁止上传 SQLite、整库内容、个人作答、错因或原图。
- 合并、恢复和同步不得静默覆盖资料；字段冲突必须进入确认流程。
- 协议先于代码；修改跨端格式或同步语义时先更新 `protocol/`。
- 数据迁移必须覆盖旧库启动、重复执行、升级前备份、失败恢复和引用完整性。
