# 全局 UI 视觉与交互重构任务书

> 状态：进行中。每完成一个页面或公共组件，必须更新本文的迁移状态和验收结果。
> 
> 范围：Windows PySide6 客户端。只重构前端视觉、交互与组件组织；不得随意修改数据库、服务接口、同步协议或领域规则。
>
> “自然柔和”组件语言的专项诊断、Qt 技术路径、实施进度与后续计划见 [`24_柔和视觉系统研究与改造计划.md`](24_柔和视觉系统研究与改造计划.md)。

## 1. 目标

将当前 Qt 原生控件拼接式界面，统一为现代、轻量、专业的学习管理产品体验：清晰、克制、长时间使用舒适，并具备明确的信息层级和完整状态反馈。

目标风格参考轻量办公与知识管理工具的设计语言，但不得复制任何第三方品牌、名称、图标、页面或插画。

## 2. 信息架构原则

1. 首页做导航和决策，子页做编辑和执行。
2. 一个页面只服务一个核心用户意图；复杂表单、批量选择器、长列表和多步骤操作必须拆入子页面。
3. 模块结构固定为：模块首页 -> 子任务页 -> 执行页。返回路径必须清晰。
4. 弹窗只用于确认、轻量选择、危险操作或不可中断提醒；完整工作流使用主内容区子页面。
5. 不把所有能力铺在一个纵向页面。桌面端优先使用合理的双栏、三栏、主从列表或详情布局。
6. 空白必须有结构：以容器、栅格、对齐和适度留白建立节奏，不能留下无意义的大块空区域。

## 3. 技术基线

| 项目 | 当前实现 |
| --- | --- |
| 前端技术 | PySide6 / Qt Widgets |
| 页面导航 | `MainWindow` + `QStackedWidget` |
| 全局样式 | `apps/windows/src/yancuo_win/ui/theme.py` |
| 公共组件 | `apps/windows/src/yancuo_win/ui/widgets.py` |
| 图标库 | 暂无。新增图标时必须统一采用同一套线性图标方案，禁止字符模拟图标。 |
| 业务状态 | 页面局部状态 + Application Service；不得为视觉重构改写业务数据模型。 |

## 4. 目标设计系统

### 4.1 颜色

| Token | 值 | 用途 |
| --- | --- | --- |
| app background | `#F5F6F7` | 主内容背景 |
| sidebar background | `#F7F8FA` | 侧栏背景 |
| surface | `#FFFFFF` | 内容表面、卡片、弹窗 |
| surface active | `#E8F0FF` | 当前项、选中行 |
| text primary | `#1F2329` | 主文字 |
| text secondary | `#646A73` | 说明文字 |
| text tertiary | `#8F959E` | 占位与弱提示 |
| border | `#DEE0E3` | 常规边框 |
| border light | `#EFF0F1` | 分隔线 |
| primary | `#3370FF` | 唯一主要操作色 |
| success / warning / danger | `#34A853` / `#F5A623` / `#F54A45` | 状态反馈 |

### 4.2 排版与尺寸

- 字体：`Inter, PingFang SC, Microsoft YaHei, system-ui, sans-serif`。
- 页面标题：20px / 600；区域标题：16px / 600；次标题：14px / 500；正文：14px；辅助文字：12px。
- 间距只使用：4、8、12、16、20、24、32px。
- 输入框与默认按钮：36px 高；紧凑控件：32px。
- 输入框、按钮：6px 圆角；卡片、弹窗：8px；大型区域：8-10px。
- 常规内容区不使用显著阴影；通过背景、边框、间距与对齐建立层级。

### 4.3 组件规范

- 一个操作区域最多一个 Primary Button；次要动作使用默认或文字按钮。
- 所有按钮、输入、下拉、列表、表格、标签、对话框统一由 `theme.py` 控制基础状态：默认、悬停、焦点、禁用、加载、错误。
- 图标按钮必须有 Tooltip；禁止 `×`、`▼`、`...` 等文本模拟图标。
- 列表行需有主标题、次信息、悬停和选中反馈；不使用纯文字堆砌数据。
- 表格不画每单元格完整边框，只保留表头与行分隔。
- 空状态必须包含简短标题、操作说明，必要时给出单个主要操作。

## 5. 应用外壳

1. 左侧导航宽度 220-240px，浅灰背景，当前项浅蓝高亮、深蓝文字。
2. 主内容背景为 `app background`，内边距 24px，内容不贴屏幕边缘。
3. 建立统一 `PageHeader`：返回、标题、说明、面包屑、页面级主要/次要操作。
4. 桌面端大于 1200px 使用完整导航；900-1200px 收窄侧栏和右侧面板；小于 900px 目录与计划草稿使用抽屉。

## 6. 页面模板

| 模板 | 适用页面 | 结构 |
| --- | --- | --- |
| 仪表盘 | 工作台、复习首页 | 概览数据 + 2-5 个任务入口 |
| 文件管理 | 题库、笔记、制定计划 | 目录树 + 内容列表 + 可选详情/草稿侧栏 |
| 列表页 | 计划列表、任务中心、搜索 | 页头 + 工具栏 + 列表/表格 + 批量操作栏 |
| 详情页 | 题目详情、笔记详情 | 页头 + 主内容 + 右侧元数据/操作 |
| 编辑页 | 手动录题、笔记编辑、设置 | 分组表单 + 固定主要提交操作 |
| 沉浸会话 | 题目复习、笔记复习 | 最少干扰的顶部进度 + 内容 + 当前动作 |

## 9. 页面迁移规则

每个页面迁移时必须：

1. 先选择页面模板，再改布局；不能只替换颜色。
2. 使用全局 token 和公共组件；不得新增硬编码颜色、随机边距或局部字体。
3. 保留服务调用、信号、数据字段和业务校验。
4. 添加或保留空、错误、禁用、确认和提交中状态。
5. 在 1366x768 与 1920x1080 下检查文字、按钮、滚动区和分栏不重叠。
6. 为高风险交互补充或更新单元测试。
7. 完成后更新本文“已完成/待迁移”状态。

## 10. 验收标准

1. 所有主要页面第一眼属于同一个产品，且不存在宋体、衬线正文、默认控件或大面积高饱和蓝按钮。
2. 首页仅展示任务入口和状态，复杂操作在子页面完成。
3. 主要页面均有明确主要动作、次要动作、禁用和反馈状态。
4. 题库、笔记和制定计划形成一致的文件管理体验。
5. 不删除或改写既有业务能力：导航、搜索、目录、批量选择、计划草稿、创建计划、复习、答案评分、笔记管理、同步与数据操作。
6. 运行以下检查：

```powershell
cd apps/windows
python -m compileall -q src/yancuo_win/ui
pytest ../../tests/unit -q
python -m ruff check src ../../tests/unit
```
