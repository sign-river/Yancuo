# 问题收集箱

这里保存用户连续提交但尚未正式排期的问题。它不是任务清单，也不记录实现细节。

## 使用流程

```text
用户提交问题
  → AI 保留原意并结构化记录
  → 必要时澄清
  → 归入一个方向分任务书
  → 获得正式任务 ID
  → 按总任务书优先级实施
  → 完成记录与 Git 提交
```

## 问题模板

复制下面的区块新增问题，编号格式为 `ISSUE-YYYYMMDD-NNN`：

```markdown
### ISSUE-YYYYMMDD-NNN · 简短标题

- 状态：待整理
- 用户原话：
- 现象与复现：
- 期望结果：
- 影响范围：
- 相关截图/日志：
- 建议方向：UI / 同步 / Android / 发布质量 / 待判断
- 正式任务：尚未归档
```

## 整理约束

- 不因问题描述中出现解决方案就直接把方案当成结论。
- 一个问题可以拆成多个正式任务，但每个正式任务只能有一个负责方向。
- 重复问题合并时保留全部原始问题 ID。
- 进入分任务书后，把状态改为“已归档”，并填写正式任务链接；不在这里复制任务状态。
- 用户明确要求立即修复时，可以边整理边实施，但仍需补齐任务 ID、验收和完成记录。
