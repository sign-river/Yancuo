## AI 维护规则

1. 用户只提交问题、建议或设计想法时，AI 只整理问题收集箱和任务书，不修改产品代码；只有用户明确要求“开始改”“实现”“按任务书继续”等，才进入实施。
2. AI 为问题补齐复现、期望、影响方向和验收方式；信息不足时标记“待澄清”。
3. 问题成熟后进入唯一一个分任务书，获得稳定任务 ID；问题收集箱只保留原始问题与任务链接。
4. 用户说“按照任务书继续”时，AI 从总任务书中选择最高优先级、未阻塞且依赖满足的任务。
5. 实现完成后先测试，再更新分任务书和完成记录，最后提交；总任务书只更新方向摘要。
6. 同一状态不得同时在研究文档、README 和多个任务书中维护。

## 状态定义

| 状态 | 含义 |
| --- | --- |
| `待整理` | 只有问题描述，尚未进入正式任务 |
| `待澄清` | 需要用户选择或缺少关键复现信息 |
| `就绪` | 目标、边界、依赖和验收条件完整，可以实施 |
| `进行中` | 当前正在实现 |
| `阻塞` | 明确依赖外部条件，暂时不能推进 |
| `已完成` | 已实现、验收、记录并提交 |
| `不做` | 经确认不进入产品范围，并记录原因 |
